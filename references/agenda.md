# Vibe Coding Workshop — Structure v2 (post-feedback)

**Target length:** 90 minutes or less (shortened after feedback)
**Status:** Draft structure — content per section to be refined later

## Flow overview

Intro → What is Vibe Coding → The Spectrum → Why Now? Models & Capabilities → Basic Software Architecture → Live Demo → Closing

---

## 1. Introduction (~5 min)

- Who I am: name, background, what I work with
- Quick framing of what the session will cover

## 2. What is Vibe Coding? (~5 min)

- Origin story: the tweet that coined "vibe coding" (Andrej Karpathy, Feb 2025 — quote the tweet directly on the slide)
- What the term means in practice: describing what you want, letting the AI write the code, "giving in to the vibes"

## 3. The Spectrum (~5 min)

- One axis: **Vibe Coding ←→ Agentic Engineering ←→ Software Engineering**
- Key framing: vibe coding is _coding_, but it is not _software engineering_ — agentic engineering sits in the middle
- Where this workshop sits: close to the vibe coding end — "a few inches to the right" — not yet at agentic engineering

## 4. Why Now? Models & Capabilities (~15 min)

**Opening question:** Why is vibe coding becoming possible _now_, rather than five years ago?

- **What is a model?** A quick, plain-language explanation of what people mean by an AI model and why different models exist
- **What changed?** A short timeline built around capability milestones—not a list of product releases—showing the progression from generating text, to writing code, to using tools, seeing interfaces, and completing multi-step tasks
- **Where are we now?** A simple map of the current frontier-model landscape and the kinds of work these models can perform today
- **The threshold we have crossed:** models are no longer only answering questions or completing snippets; they can increasingly participate in the full loop of building, checking, and iterating on software
- **Why this moment is unique:**
  - The capability is powerful enough to turn natural-language intent into working software
  - The tools are accessible enough that a beginner can start without first mastering the entire technical stack
  - The learning loop is dramatically shorter: you can make something, see the result, ask why it works, and improve it in the same session
  - We are still early—the tools are imperfect and judgment still matters—which makes now a valuable time to learn how to work with them

**Closing beat:** The barrier to _starting_ has collapsed, while the ceiling of what you can build keeps rising. That combination is why now is an unusually good time to learn.

Transition: "But to direct these tools well, we still need a map of what we are building." → basic software architecture

## 5. Basic Software Architecture (~10 min)

- What is code, what is an application
- The shape of an app: **client → server → database** (how they connect)
- How deployment works — where your app actually lives when it's "live"
- Deliberately stays at the architecture level; **do not go down into code**

## 6. Live Demo (~35–40 min)

- **Idea comes from the audience** — take inspiration directly from the room
- Build it no matter how hard it is; see how far we can go
- **Goal 1:** get _something_ built and **deployed** — shipping is the win
- **Goal 2:** gather feedback from the audience and iterate toward something more complex, as far as time allows

## 7. Closing (~5 min)

- Show the vibe coding skill tiers (beginner → intermediate → advanced)
- Position the workshop: "this course gets you to **intermediate**"
- End on an inspirational note
